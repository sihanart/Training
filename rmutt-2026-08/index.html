01

ภาพรวมสถาปัตยกรรม

ใช้คู่กับหัวข้อ Overview Aruba Solution — อธิบายบทบาทของอุปกรณ์แต่ละชั้น และเส้นทางเดินของ traffic ทั้งฝั่ง wired และ wireless

① Wired flow

PC » Access switch (VLAN / 802.1X) » Core (routing, DHCP relay) » Firewall » Internet

② Wireless flow — Tunnel mode

Client » AP » GRE tunnel ผ่าน switch/core » Mobility Controller » ปล่อยลง VLAN » Internet

Device roles

Switch = ต่อ/จ่ายไฟ · Core = routing + DHCP relay · Controller = SSID, role, policy · ClearPass = ตัดสินใจตัวตน

02

Lab topology (แบ่งตาม Pod)

Pod ละ 2–3 คน แต่ละ Pod ได้อุปกรณ์ชุดเดียวกัน แยก VLAN และ SSID กันคนละชุด เพื่อให้ config ทับกันไม่ได้ — ครอบทุกหัวข้อของ Module 1 และ Module 2

Module 1 — ทำที่สวิตช์

VSF stack, LAG 2x10G ขึ้น core, PoE+ จ่ายไฟ AP, VLAN, SVI + routing, DHCP relay, 802.1X ฝั่ง wired

Module 2 — ทำที่ Controller + AP

AP onboarding ผ่าน GRE tunnel, สร้าง 3 SSID ต่อ Pod (PSK / Captive portal / 802.1X / MAC auth), User role + AppRF policy, Dashboard

ถ้าอุปกรณ์ไม่พอ

ใช้ Mobility Controller ตัวเดียวร่วมกันได้ โดยแยก WLAN/AAA profile ต่อ Pod · ClearPass 1 VM เพิ่ม NAD ทุก Pod

03

แผน VLAN / IP

n คือหมายเลข Pod — Pod 1 ใช้ VLAN 11–15 กับ 10.1.x.0/24, Pod 2 ใช้ VLAN 21–25 กับ 10.2.x.0/24 ไล่ไปเรื่อยๆ

VLANชื่อ / การใช้งานSubnetหมายเหตุ
n1MGMT (Switch / AP)10.n.1.0/24จัดการอุปกรณ์ — ไม่ปนกับ user
n2Wired Users — 802.1X10.n.2.0/24ทดสอบ 802.1X ฝั่ง wired (Module 1)
n3WLAN Employee — 802.1X10.n.3.0/24SSID PODn-EMP · EAP-PEAP / EAP-TLS
n4WLAN Guest — Captive portal10.n.4.0/24SSID PODn-GUEST · Guest role จำกัดสิทธิ์
n5WLAN IoT — PSK + MAC Auth10.n.5.0/24SSID PODn-IOT · ใช้สอน MAC Authentication
100Transit / Internet uplink192.168.100.0/24Default route → 192.168.100.254
200Servers192.168.200.0/24MC 192.168.200.10 · CPPM .20 · DHCP/DNS .30

Gateway ของทุก VLAN อยู่บน core (ip address 10.n.x.1/24) และชี้ DHCP ด้วย ip helper-address 192.168.200.30
