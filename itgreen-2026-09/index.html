ก่อนวาง config

เช็คว่าต่อ console/SSH ถูก controller ของชุดตัวเอง ด้วย show running-config | include vlan ก่อนเสมอ

เช็คหลังวาง

show ip dhcp binding ต้องมี AP ขึ้น · show ap active ต้องเห็น AP ของชุดตัวเอง · ping ออกเน็ตจาก client ต้องผ่าน

ถ้า config ผิดชุด

ลบ VLAN ที่สร้างผิดด้วย no interface vlan <id> และ no ip dhcp pool <name> แล้วค่อยวางชุดที่ถูกใหม่

05

Lab ทีละขั้น

7 ชุดทำพร้อมกันได้ — LAB 1–7 บน PNETLAB · LAB 8–14 บน Controller VM ของชุด

LAB 1–7 ฝึกบน PNETLAB — ห้องแลบของชุดตัวเองมีสวิตช์จำลอง 3 ตัวและ PC 3 เครื่อง พังได้ reset ใหม่ได้ · LAB 8–14 ทำบน Controller VM ของชุดตัวเอง ค่าที่ต้องแทนอยู่ในหัวข้อ Config ด้านบน (n = หมายเลข Pod)

อุปกรณ์จริงที่ใช้ร่วมกัน — Aruba 9004-LTE (หัวสาย RAP), AP-515 และ Aruba CX 6100 — ผู้สอนเป็นคนคุม เพราะเป็นทางผ่านของทุกชุด · หลักสูตรนี้ไม่แตะ VSX, Spanning-tree และ OSPF ตามที่ course outline ระบุว่าเป็นเนื้อหาหลักสูตร Advance

LAB 1

เข้า PNETLAB และตั้งค่าเริ่มต้นให้สวิตช์

PNETLAB (สวิตช์จำลอง)

เข้าห้องแลบของชุดตัวเองได้ เห็นสวิตช์ครบสามตัว ตั้งรหัส admin และ hostname ให้ครบทุกตัว

  1. เปิด http://10.69.11.10/ แล้วล็อกอินด้วยผู้ใช้ของชุดตัวเอง — POD 1 ใช้ pod1 รหัส P@ssw0rd
  2. เปิด lab ของชุดตัวเอง กด START แล้วรอให้สวิตช์ทั้งสามตัวขึ้นครบ
  3. คลิกที่สวิตช์ตัวแรกเพื่อเปิด console — ครั้งแรกล็อกอินด้วย admin แล้วเคาะ Enter ผ่านช่องรหัส จากนั้นระบบจะบังคับให้ตั้งรหัสใหม่ ตั้งเป็น Aruba123! ให้เหมือนกันทั้งชุดจะได้ไม่ลืม
  4. ตั้ง hostname ให้ตรงกับผัง FIG.03
    configure terminal
hostname CX-SW-1
exit
write memory
  5. ทำซ้ำข้อ 3–4 กับอีกสองตัว ตั้งชื่อเป็น CX-SW-2 และ CX-SW-3
  6. จดไว้ใช้ทั้งวัน: สวิตช์ 192.168.0.2 / .3 / .4 · VLAN 10 / 20 / 30 · Controller ของชุดคือ 192.168.10.22n

ทุกคนในชุดใช้ล็อกอิน PNETLAB เดียวกัน — ถ้าสองคนกดพร้อมกันจะแย่ง console ตกลงกันก่อนว่าใครทำสวิตช์ตัวไหน

exit
write memory

LAB 3

Clock, Timezone, DNS และ SNMP

PNETLAB (สวิตช์จำลอง)

ให้เวลาบนสวิตช์ตรง และตั้งค่าที่ระบบ monitoring ต้องใช้ — log ที่เวลาผิดคือ log ที่ไล่ปัญหาไม่ได้

  1. ตั้ง timezone แล้วค่อยตั้งเวลา — สลับลำดับกันเมื่อไหร่เวลาจะเพี้ยนไปตามโซนเดิม
    configure terminal
clock timezone asia/bangkok
clock date 2026-09-03
clock time 09:00:00
  2. ชี้ NTP ไว้ด้วย จะได้ไม่ต้องมาตั้งมือทุกครั้งที่ reset
    ntp server pool.ntp.org
ntp enable
  3. ตั้ง DNS
    ip dns server-address 8.8.8.8
ip dns server-address 1.1.1.1
ip dns domain-name lab.local
  4. ตั้ง SNMP สำหรับอ่านค่า
    snmp-server community public
snmp-server system-location &quot;Training Room&quot;
snmp-server system-contact &quot;IT Green&quot;
exit
write memory
  5. เช็คว่าเวลาขยับจริง — เคาะ show clock สองครั้งห่างกันสักครู่ ตัวเลขต้องเดิน
ตรวจผลshow clockshow ntp statusshow ip dnsshow snmp-server

clock timezone ต้องพิมพ์เป็นตัวเล็กทั้งหมดแบบ asia/bangkok — พิมพ์ Asia/Bangkok สวิตช์จะไม่รู้จัก

LAB 4

Checkpoint, Diff และ Rollback

PNETLAB (สวิตช์จำลอง)

เซฟจุดที่ config ยังดีอยู่ แล้วย้อนกลับมาได้เมื่อพังในแลบถัดไป — นี่คือตาข่ายรองของทั้งวัน

  1. เซฟ checkpoint ก่อนเริ่มแตะ VLAN ตั้งชื่อให้รู้เรื่อง
    configure terminal
exit
copy running-config checkpoint BEFORE-VLAN
  2. ลองแก้อะไรสักอย่างให้ต่างจากเดิม
    configure terminal
vlan 99
    name TEST-DIFF
exit
  3. เทียบดูว่าต่างจากจุดที่เซฟไว้ตรงไหน — ต้องเห็นแค่ VLAN 99 ที่เพิ่งเพิ่ม
    checkpoint diff BEFORE-VLAN running-config
  4. ย้อนกลับไปจุดเดิม แล้ว diff ซ้ำ คราวนี้ต้องไม่มีอะไรต่าง
    checkpoint rollback BEFORE-VLAN
checkpoint diff BEFORE-VLAN running-config
  5. ลองโหมด auto rollback — สั่งแล้วมีเวลานับถอยหลัง ถ้าไม่ confirm ทันจะย้อนกลับเอง เหมาะกับตอนแก้ config ผ่าน SSH ที่อาจตัดตัวเองหลุด
    configure terminal
checkpoint auto 5
exit
  6. ยืนยันว่ายังคุยกันได้อยู่ ให้ config ที่แก้อยู่ต่อ
    checkpoint auto confirm
ตรวจผลshow checkpointshow checkpoint BEFORE-VLANshow checkpoint auto

checkpoint auto ที่ลืม confirm จะย้อน config กลับเงียบ ๆ ตอนหมดเวลา — ถ้าอยู่ ๆ ของที่เพิ่งตั้งหายไป ให้สงสัยข้อนี้ก่อน

  1. สร้าง VLAN ทั้งสามวงให้เหมือนกันทั้งสามตัว — เริ่มที่ CX-SW-1
