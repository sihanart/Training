03

แผน VLAN / IP

2601–2608 เป็น AP VLAN ของแต่ละชุด — ไม่มี VLAN สวิตช์เพราะคอร์สนี้ไม่มีเนื้อหาสวิตช์

VLANชื่อ / การใช้งานSubnetหมายเหตุ
2601–2607AP VLAN ของ POD 1–710.26.n.0/24n = หมายเลข Pod · gateway 10.26.n.1 บน controller ของชุดนั้น
2608AP VLAN ของชุดผู้สอน10.26.8.0/24ผู้สอนสาธิตก่อน แล้วให้แต่ละชุดทำตามบนของตัวเอง
MGMTController ของแต่ละชุด192.168.10.221–227Pod n » 192.168.10.(220+n) · ผู้สอน 192.168.10.133
DHCPช่วงที่ controller แจกให้ AP10.26.n.11–.240exclude .1–.10 และ .241–.254 · lease 8 ชม.

หลักสูตรนี้มีแค่ VLAN ฝั่ง AP วงเดียว — ไม่มี VLAN ของแลบสวิตช์เพราะไม่มีเนื้อหาสวิตช์ · Gateway ของ AP VLAN อยู่บน controller ของชุดนั้นเอง (interface vlan 260n · ip address 10.26.n.1) และ controller ทำ DHCP เอง จึงไม่ต้องใช้ relay

ถ้าหลงไปแก้ผิดชุด

DEMO

AP ไม่ขึ้นระบบ

ผู้สอนสาธิต (Demo — ไม่ต้องลงมือเอง)

ดูผู้สอนไล่หาสาเหตุที่ AP ไม่ขึ้นระบบสองสถานการณ์ จดลำดับการวินิจฉัยไว้ใช้เป็นเช็คลิสต์

  1. อ่านสถานะจาก AP LED ก่อนเปิดคอมพิวเตอร์ — กะพริบเขียวช้า ๆ = กำลัง boot, กะพริบเขียว-เหลืองสลับ = หา DHCP/controller ไม่เจอ, เขียวติดค้าง = เชื่อมสำเร็จแล้ว
  2. สถานการณ์ที่ 1 — AP ค้างที่ "searching": เช็คว่า AP ขอ IP มาหรือยัง ถ้าไม่มีในลิสต์ แปลว่าปัญหาอยู่ที่ VLAN/DHCP ไม่ใช่ตัว AP
    show ip dhcp binding
show vlan
show ip interface brief
  3. สาเหตุที่พบบ่อยของสถานการณ์ที่ 1: AP เสียบผิดพอร์ตเข้า VLAN ของชุดอื่น, DHCP pool เต็มหรือถูกปิดไว้
  4. สถานการณ์ที่ 2 — AP ได้ IP แล้วแต่ไม่ขึ้น Active: เช็คว่ายังค้างใน Allowlist รอ Approve อยู่ไหม
    show ap database
show ap allowlist
  5. สาเหตุที่พบบ่อยของสถานการณ์ที่ 2: ลืม Approve ใน Allowlist, Country code ไม่ตรงกับ Controller, เวลาเครื่อง (clock) เพี้ยนกันมากจน certificate ตรวจสอบไม่ผ่าน
ตรวจผลshow ip dhcp bindingshow ap databaseshow ap allowlist

จำไว้แค่ลำดับเดียว: LED → show ip dhcp binding → show ap database → show ap allowlist แยกให้ออกว่าปัญหาอยู่ก่อนหรือหลัง AP ได้ IP เพราะสองช่วงใช้คำสั่งคนละชุด

LAB 1

Client ต่อ WLAN ไม่ได้

Controller VM ของชุด

Controller มี SSID สี่แบบตั้งไว้แล้ว (PSK, MAC, 802.1X, Captive Portal) แต่ละตัวถูกใส่ปัญหาไว้หนึ่งอย่าง — หาให้เจอแล้วแก้ให้ client ต่อผ่าน

  1. SSID แบบ PSK: เช็ค Key management ตรงกับ client ไหม (WPA2 vs WPA3-only) และเทียบ passphrase ในเครื่องกับใน config
    show wlan ssid-profile
show ap active
  2. SSID แบบ MAC Authentication: เช็ครูปแบบ MAC ในฐานข้อมูล — ต้องเป็นตัวพิมพ์เล็กไม่มีขีด/จุดคั่น (aabbccddeeff)
    show local-userdb
show user-table
  3. SSID แบบ 802.1X: เช็คว่า Authentication server ชี้เป็น Internal และผู้ใช้ทดสอบมีอยู่จริงพร้อมรหัสตรงกัน
    show aaa authentication-server internal
show user-table
  4. SSID แบบ Captive Portal: ถ้าหน้า Login ไม่เด้ง ให้เช็คว่า role ก่อนล็อกอิน (logon) อนุญาต DNS ออกไปได้ไหมก่อน
    show user-table
show aaa authentication captive-portal
ตรวจผลshow wlan ssid-profileshow user-tableshow local-userdb

MAC ใส่ผิดรูปแบบ (มีขีดหรือจุดคั่น) จะไม่ error แต่ไม่แมตช์อะไรเลย — และ role ก่อนล็อกอินที่ปิด DNS คือสาเหตุอันดับหนึ่งที่หน้า Captive Portal ไม่เด้ง

LAB 2

Role/Policy และ Dashboard

Controller VM ของชุด

ปัญหาที่ authentication ผ่านแล้วแต่พฤติกรรมเครือข่ายยังไม่ถูกต้อง — ต้องอ่านผลจาก Dashboard และ show command แทน error

  1. Policy ไม่ทำงานตามที่ตั้งไว้: เช็คลำดับกฎ — กฎแรกที่แมตช์คือกฎที่ใช้จริง permit any ที่อยู่เหนือ deny จะทำให้ deny ไม่มีวันทำงาน
    show rights
show netdestination
show acl brief
  2. แก้ policy แล้วเครื่องเดิมยังไม่เปลี่ยนพฤติกรรม เพราะ role ผูกกับ session ที่ค้างอยู่แล้ว — ต้องตัดแล้วต่อใหม่
  3. ไล่ปัญหาด้วย Dashboard: Overview (ภาพรวม) → Access Points (AP ตัวเอง active ไหม) → Clients (SSID/role/RSSI ของเครื่องที่ต่ออยู่) → Applications/AppRF (ใช้แอปอะไรอยู่ เทียบกับ policy)
  4. เช็คลิสต์วินิจฉัยครบวงจร: AP active? → Client เห็น SSID? → Authentication ผ่านหรือติดขั้นไหน? → ได้ IP ไหม? → Role ตรงไหม?
    show ap active
show user-table verbose
show ip dhcp binding
show ap debug client-table
ตรวจผลshow rightsshow user-table verboseshow ap active

Dashboard รีเฟรชเป็นรอบ ไม่ใช่ real-time เป๊ะ — เพิ่งแก้ config แล้ว Dashboard ยังไม่อัปเดต ให้รอสักครู่ก่อนสรุปว่าค้าง
